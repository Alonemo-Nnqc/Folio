## 2. 元数据检索引擎在线评测（META-02/06）

样本：从你的 Zotero 库复制出 49 篇 PDF，文件名匿名化（`NN.pdf`），用 Zotero 中的标题和 DOI 作为真值。其中 28 篇是原版 PDF，21 篇是翻译插件生成的中英对照版（`*.compare.pdf`）。4 个文件并发检索，和 App 的行为一致。

| 样本 | 篇数 | 命中 | 错误匹配 | P50 | P90 |
| --- | --- | --- | --- | --- | --- |
| 原版 PDF | 28 | 28（100%） | 0 | 2.06 s | 4.23 s |
| 中英对照版 | 21 | 21（100%） | 0 | 2.81 s | 4.58 s |
| CVF 会议论文（你 Zotero 中的 6 篇 CVPR/ICCV + 4 篇 CVPR 2026，文件名匿名化） | 10 | 10（100%） | 0 | 1.5–2.5 s | 5.5 s |

- 需求目标"中位数 ≤ 3 s，90% ≤ 5 s"：原版和对照版都达标（09-27 复测）。
- 对照版有 1 篇在那次运行中遇到 Crossref 临时失败，被正确判为"网络错误"；App 会在网络恢复后自动重试。单独重跑这一篇时，1.7 s 命中。
- DBLP 的接口目前对所有请求返回反爬虫验证页，暂时无法使用；CVF 会议论文改由 CVF 开放获取网站直接获取。
- OpenAlex 现在对不带 API Key 的请求按 IP 计量每日额度，额度用完会返回 429。引擎在没有 OpenAlex 的情况下仍能达到上面的结果；设置中可以选填 OpenAlex API Key。

复现命令：
```
cd Packages/FolioCore
FOLIO_LIVE=1 FOLIO_EVAL_DIR=/tmp/folio-eval FOLIO_EVAL_TRUTH=/tmp/folio-eval-truth.json swift test --filter LiveEvaluation
```

## 3. Zotero 导入端到端（ZOT-01…06）

数据源是 `~/Zotero` 的只读副本。

- **读取统计**：70 个常规条目、22 个独立附件、9 个分组（三级分组已压平）、2 个手动标签，另有 55 个自动标签可选。
- **跳过的内容**：11 条笔记、118 条 Zotero 批注、16 个网页快照、1 个链接网址、1 个回收站条目。
- **导入到 Folio**：导入 79 个条目、115 个文件，新建 9 个分组、2 个标签。
  - 跳过 13 个重复项：同一 PDF 或同一篇文献在 Zotero 中存了多份。
  - 有 2 个附件在 Zotero 里本身就是空记录（没有路径），找不到对应文件。
  - 整个导入耗时 0.63 s。
- **重复导入**：第二次导入新增 0 个条目，去重生效。

## 4. 性能（4.18）

测试库由 `folio-seed bulk` 生成：1000 个条目、10 个分组、8 个标签。使用 Release 构建，App 在后台启动（`script/perf.sh`）。

| 指标 | 目标 | 结果 |

| 常驻内存（1000 条目，全文索引已建好） | < 150 MB | 114–123 MB ✅ |
| 常驻内存（12 条目演示库） | — | 96 MB |

⚠️ 一次性导入上千篇 PDF 并建完全文索引后，内存会暂时停在约 160 MB，这部分是 PDFKit 和 CoreGraphics 的全局缓存。重新启动后回到 114–123 MB。日常逐篇导入不会出现这种情况。
