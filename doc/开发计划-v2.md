# Folio v2.0 开发计划

> 依据：`doc/需求文档.md` v2.0。参考规范：macos-native-app 技能（AppKit 骨架 + SwiftUI 承载检查器 / 设置 / 弹窗）。
>
> 执行方式：两个与界面无关、互相独立的模块（Zotero 识别服务、翻译引擎）各开一个 git worktree 和分支，交给子 agent 并行开发；主 agent 在 `main` 上完成数据层、原生外壳、阅读器、笔记，最后合并两个分支、接入界面并做全面验收。每个任务完成后编译、测试通过并提交（Conventional Commits）。

## 全局约束（沿用 v1，新增项标 ★）

- macOS 26.0+，Xcode 27 / Swift 6.4，Swift 6 语言模式，App target 默认 MainActor 隔离。
- 签名：Apple Development，Team `2WJC7GTSV4`；不开沙盒，开启 Hardened Runtime。
- 不得写入 `~/Zotero`、`~/Folio`（用户真实数据）；测试一律使用临时文献库或数据副本。
- 截图只截 Folio 自己的窗口（`script/preview.sh`）。不运行会操作鼠标键盘的自动化。
- ★ 翻译组件（约 1 GB）不得打进 App 包，只能按需下载到 `~/Library/Application Support/Folio/Translator/`。测试时用临时目录。
- ★ 用户可见行为改动时，同一提交更新 README / 需求文档。

│   ├── ReaderSplitViewController.swift    缩略图/目录/批注/查找 侧栏 + PDFView + 笔记检查器

├── Notes/                         ★ NoteEditorView（NSTextView + Markdown 着色），检查器和阅读器共用
├── Translation/                   ★ TranslationCoordinator（队列、进度、结果入库）、TranslationSettingsView

## 二、阶段与任务

### 阶段 1 数据层（主 agent，main）

1. 迁移 `v2`：
   - `note(itemId TEXT PK REFERENCES item ON DELETE CASCADE, content TEXT NOT NULL, dateModified DATETIME NOT NULL)`
   - `readingState(fileId TEXT PK REFERENCES file ON DELETE CASCADE, pageIndex INT, pointX REAL, pointY REAL, scale REAL, autoScale BOOL, displayMode INT, dateModified DATETIME)`
   - `file` 增加 `translationOf TEXT`、`translationKind INTEGER`（0 纯译文 / 1 双语）
2. `Library` API：`note(for:)`、`setNote(_:for:)`、`readingState(fileId:)`、`saveReadingState(_:)`、`addTranslatedFile(at:of:kind:name:)`。
3. 快照：`notedItems: Set<String>`；`searchText` 拼入笔记内容；`readingState` **不进入**快照，避免翻页触发列表刷新。
4. 单元测试：迁移、笔记增删改与级联删除、阅读位置读写、译文文件入库与命名、笔记参与搜索、彻底删除时清理。

### 阶段 2 原生外壳（主 agent）

1. `main.swift` + `AppDelegate` + `MainMenu`；删除 `FolioApp`、`FolioCommands`、`RootView`、`SidebarView`、`ItemListView`、`SidebarOutline`、`ItemOutline`、`SidebarSearchField`。
2. `LibraryWindowController`：`.fullSizeContentView`、`tabbingIdentifier`、`.fullScreenPrimary`、frame autosave。
3. `LibrarySplitViewController`：`NSSplitViewItem(sidebarWithViewController:)` / `(viewController:)` / `(inspectorWithViewController:)`，`splitView.autosaveName`。
4. 工具栏：`.toggleSidebar`、`.sidebarTrackingSeparator`、添加（`NSMenuToolbarItem`）、阅读、翻译、导出（`NSMenuToolbarItem`）、`NSSearchToolbarItem`、`.inspectorTrackingSeparator`、`.toggleInspector`；`allowsUserCustomization`、`autosavesConfiguration`；窗口标题 = 视图名，副标题 = 条目数。
5. 侧栏：去掉自绘顶部行；增加\"分组\"区标题（右侧 + 按钮）与底部\"新建分组\"按钮；保留内置分组、两级分组、标签区和全部拖放规则。
6. 列表：搜索范围栏（当前分组 / 全部文献 / 包含 PDF 全文）、空状态、拖入浮层、轻提示改为 AppKit 控制器中的 NSHostingView 叠加层；笔记图标；译文标识；翻译进度。
7. 弹窗：`activeSheet` 由窗口控制器观察并用 `presentAsSheet` 弹出 SwiftUI 内容；所有 NSOpenPanel / NSSavePanel / NSAlert 改为窗口内 sheet。
8. 设置窗口：`NSTabViewController(.toolbar)` + 每页 `NSHostingController(Form.grouped)`；⌘, 打开。
9. 预览钩子（`PreviewHooks`）、模拟拖放（`SimulatedDrop`）迁移到新结构，保证截图脚本可用。

### 阶段 3 阅读器（主 agent）

1. `ReaderWindowController` + 原生标签页；同一文件只开一个标签。
2. PDFView 浏览：缩放、显示方式、翻页、前往页面、查找（工具栏搜索框 + 侧栏结果列表）、缩略图、目录、批注列表。
3. 批注：工具状态机（选择 / 高亮 / 下划线 / 删除线 / 便签 / 文本框 / 手绘）、颜色、选中与移动、删除、右键菜单、撤销重做（窗口 undoManager）。
4. 保存：防抖 1 秒原子写回（写临时文件 → `replaceItemAt`）；保存后通知 `ImportCoordinator.refreshChangedFiles()`。
5. 阅读位置：滚动停止 1 秒后与关闭时保存；打开时恢复。启动时恢复上次的标签页。
6. 笔记检查器（阅读器右栏）与\"添加到笔记\"。
7. 对照阅读：有译文时显示\"对照阅读\"开关，原文 + 译文两个 PDFView 按页同步。

### 阶段 4 笔记（主 agent）

`NoteEditorView`（NSTextView，Markdown 语法着色、自动保存）；检查器\"笔记\"页；列表笔记图标与可选列；导出 .md。

### 阶段 5 子 agent 并行模块

#### A. Zotero 识别服务（分支 `feat/zotero-recognizer`，只改 `Packages/FolioCore/Sources/FolioMetadata`、其测试和 `doc/检索评测-v2.md`）

- `RecognizerPayload`：用 PDFKit 复刻 Zotero pdf-worker 的 `getRecognizerData`。取前 5 页；每个单词输出 `[xMin, yMin, xMax, yMax, fontSize, spaceAfter, baseline, rotation, underlined, bold, italic, colorIndex, fontIndex, text]`，y 轴以页面顶部为原点，数值保留 4 位小数；页面结构 `[width, height, [[[[0,0,0,0,lines]]]]]`；附 `metadata`（PDF 文档信息）、`totalPages`、`fileName`。
- `ZoteroRecognizerClient`：POST `https://services.zotero.org/recognizer/recognize`，JSON 请求体，User-Agent 标明 Folio；解析返回的 type、title、authors（firstName / lastName）、abstract、year、container、volume、issue、pages、publisher、url、ISSN、ISBN、doi、arxiv、language。
- 接入 `MetadataEngine.resolve(pdfAt:)`：与现有标识符查询、标题检索同时启动。
  - 返回 arXiv / DOI / ISBN 时走现有 `lookup`，结果按现有规则在首页核对标题。
  - 只返回字段时：标题与首页文字核对通过（复用 `CandidateScorer`）才采用。
  - 优先级：PDF 自身标识符 > 识别服务给出的标识符 > 识别服务字段 > 标题检索。
  - 识别服务失败（网络、5xx、超时 4 秒）不影响原流程，也不把结果判为 networkError。
- 配置 `MetadataEngineConfiguration.useZoteroRecognizer`（默认开）。
- 测试：payload 结构（用测试里生成的 PDF）、响应解析（fixture）、引擎优先级（mock HTTP）。
- 在线评测：从 `~/Zotero` **复制** `zotero.sqlite` 到临时目录后只读读取，取有父条目的 PDF 附件为样本，以 Zotero 中的标题 / DOI / 年份为真值；对比\"旧引擎\"与\"新引擎\"的准确率、耗时中位数与 P90，写入 `doc/检索评测-v2.md`。不得修改 `~/Zotero` 下任何文件。

#### B. 翻译引擎（分支 `feat/translation-engine`，新增 `Packages/FolioCore/Sources/FolioTranslate` 及其测试和 `doc/翻译引擎-v2.md`；`Package.swift` 只新增 target / product）

- 已验证的事实：`uv tool install --python 3.12 pdf2zh-next` 安装的 2.9.0 版需要额外 `--with "bitstring<5"`，否则 `ImportError: BitStream`；环境约 880 MB；服务开关为 `--siliconflowfree --openai --aliyundashscope --google --bing --deepl --deepseek --ollama --xinference --azureopenai --modelscope --zhipu --siliconflow --tencentmechinetranslation --gemini --azure --anythingllm --dify --grok --groq --qwenmt --openaicompatible --claudecode --clitranslator`。
- `TranslatorInstallation`：基础目录可注入；状态检测（未安装 / 已安装＋版本 / 损坏）；安装（找不到 uv 时从 astral-sh/uv 官方发布页下载对应架构的二进制；设置 `UV_TOOL_DIR`、`UV_TOOL_BIN_DIR`、`UV_PYTHON_INSTALL_DIR`、`UV_CACHE_DIR` 到基础目录内；固定版本安装；`--warmup` 预下载资源）；进度回调；卸载；使用自定义可执行文件路径。
- `TranslationServiceCatalog`：上面全部服务，每个服务的开关参数、字段（参数名、标题、是否密钥、默认值、是否必填），与 `--help` 对齐（用 help 输出做测试夹具）。
- `TranslationOptions` → 命令行参数：源 / 目标语言、`--no-mono` / `--no-dual`、`--use-alternating-pages-dual`、`--pages`、`--glossaries`、`--translate-table-text`、`--enhance-compatibility`、`--qps`、`--output`、`--watermark-output-mode no_watermark`。
- `TranslationJob`：启动进程（独立进程组），解析进度（研究 `--report-interval` 的输出，或用随附的 Python 驱动脚本调用 `pdf2zh_next.high_level` 的流式接口输出 JSON 行，选更稳的一种），产出 `AsyncStream<TranslationEvent>`：`.stage(String)`、`.progress(Double)`、`.finished(mono: URL?, dual: URL?)`、`.failed(message:logURL:)`；取消时结束整个进程组；完整日志写文件。
- `SecretStore`：钥匙串读写（service `com.nnqc.Folio.translation`）。
- Apple 离线翻译：阅读 pdf2zh_next 的 clitranslator 协议，实现使用 Translation 框架（`TranslationSession(installedSource:target:)`）的命令行翻译器，作为 `FolioTranslate` 中的库代码 + 一个 executable target；如果命令行进程无法使用 Translation 框架，把结论写进文档（主 agent 将改为由 App 可执行文件的命令行模式承担）。
- 验证：用临时目录真实安装；用免费服务（siliconflowfree / bing / google 任一可用的）翻译一篇 PDF 的第 1 页，确认产出纯译文和双语 PDF、进度事件正常、取消有效。结论写入 `doc/翻译引擎-v2.md`。

### 阶段 6 集成（主 agent）

1. 合并 A：设置\"检索\"页增加\"使用 Zotero 识别服务\"开关和说明；`engineRevision` 升到 3（此前失败的 PDF 自动重试一次）。
2. 合并 B：`TranslationCoordinator`（队列、进度显示、入库、失败处理）、设置\"翻译\"页（安装 / 卸载 / 服务与字段 / 选项）、菜单和工具栏入口、阅读器对照阅读。

### 阶段 7 全面排查与验收（主 agent）

1. 逐文件代码审查（并发、内存、错误处理、菜单验证、键盘焦点、深色模式、本地化文案），修复发现的问题并记录到问题记录。
2. 单元测试全部通过：`swift test` + `FolioTests`。
3. 截图检查所有界面（浅色 / 深色）：主窗口、搜索、侧栏、检查器三页、阅读器（批注、侧栏各页、对照阅读）、设置各页、弹窗、标签页。
4. 用模拟钩子验证真实入口：拖入、双击打开阅读器、批注保存后被\"预览\"读取（PDFKit 重新打开校验）、阅读位置恢复、翻译完整流程（免费服务）。
5. 性能：1000 条目冷启动 < 1 s、常驻内存 < 150 MB（未打开阅读器时）。
6. 更新 README、测试报告、开发进度、问题记录。

## 三、合并顺序

阶段 1 → 阶段 2（期间 A、B 并行）→ 合并 A → 阶段 3、4 → 合并 B → 阶段 6 → 阶段 7。
