# 翻译引擎（v2.0，阶段 5 → B）

本文记录 `FolioTranslate` 模块的设计、实测结果和已知问题。模块位于 `Packages/FolioCore/Sources/FolioTranslate`，另有命令行工具 `folio-apple-translate`（`Sources/FolioAppleTranslate`）。模块没有界面，界面、设置页、队列由主 agent 在阶段 6 集成。

实测环境：MacBook（Apple Silicon，macOS 26 / Darwin 27），Swift 6.4，uv 0.12.6，pdf2zh-next 2.9.0（BabelDOC 0.6.2），2026-10-11。

## 1. 结论速览

| 项目 | 结果 |
| --- | --- |
| 安装方式 | uv 安装 Python 3.12 + `pdf2zh-next==2.9.0 --with "bitstring<5"`，全部放在基础目录内 |
| 安装大小 | 约 1.35–1.39 GB（虚拟环境 881 MB + Python 66 MB + 版面模型 / 字体 337 MB + 需要时下载的 uv 36 MB）；安装期间 uv 缓存另占约 930 MB，装完删除 |
| 安装耗时 | 本机没有 uv、缓存为空的全新安装实测 185 s（下载 uv 15 s、Python + 133 个软件包 134 s、资源 32 s、自检 4 s）；网络不同会有差异 |
| 进度获取 | 随附 Python 驱动脚本调用 `pdf2zh_next.high_level.do_translate_async_stream`，逐条输出 JSON 事件（方案 b） |
| 免费服务实测 | SiliconFlow 免费 ✅、Bing ✅、Google ❌（本机网络下被 Google 返回 HTTP 429 限流）；第 1 页 34–50 s，14 页全文（Bing）187 s |
| 取消 | 结束整个进程组；事件流在取消后 0.03 s 结束，4 s 后进程组内无残留进程 |
| Apple 离线翻译 | 命令行进程可以使用 Translation 框架；本机未下载语言包，只验证到“缺少语言”的报错链路，未验证实际译文 |

## 2. 目录布局与资源位置

App 使用 `TranslatorInstallation.defaultBaseDirectory` = `~/Library/Application Support/Folio/Translator/`：

```
Translator/
  uv/uv                   本机找不到 uv 时，从 GitHub 下载的官方 uv（固定 0.12.6，校验 SHA-256）
  tools/pdf2zh-next/      pdf2zh_next 的虚拟环境（UV_TOOL_DIR）
  bin/pdf2zh_next         入口脚本（UV_TOOL_BIN_DIR）
  python/                 uv 管理的 CPython 3.12（UV_PYTHON_INSTALL_DIR）
  python-bin/             UV_PYTHON_BIN_DIR（通常为空）
  cache/                  安装期间的 uv 缓存（UV_CACHE_DIR），安装成功后删除
  home/                   引擎 Python 进程眼中的 `~`
    .cache/babeldoc/      版面模型（models）、字体（fonts）、cmap、tiktoken、BabelDOC 缓存
    .cache/pdf2zh_next/   译文缓存（cache.v1.db，相同原文不重复请求）
    .config/pdf2zh/       pdf2zh_next 自动写入的默认配置
  driver/folio_pdf2zh_driver.py   Folio 的驱动脚本（每次运行前按内容更新）
  logs/                   install-*.log、translate-*.log（卸载时保留）
  tmp/                    引擎的 TMPDIR（BabelDOC 中间文件）
  installation.json       安装完成标记（版本、uv 版本、时间）
```

### 2.1 为什么要重定向 `~`

阅读安装后的源码发现，资源和配置路径都写死在用户主目录：

- `babeldoc/const.py`：`CACHE_FOLDER = Path.home() / ".cache" / "babeldoc"`（模型、字体、cmap、tiktoken 都在这里，并在导入时设置 `TIKTOKEN_CACHE_DIR`）。
- `pdf2zh_next/translator/cache.py`：译文缓存 `Path.home() / ".cache" / "pdf2zh_next"`。
- `pdf2zh_next/const.py`：配置 `~/.config/pdf2zh/config.v3.toml`。**命令行模式会读取并合并这个用户配置文件**，用户自己用过 pdf2zh 时，其中的设置会混进 Folio 的翻译。

没有环境变量或命令行选项能改这些路径。直接把 `HOME` 改掉虽然有效，但会让 Claude Code 等需要真实 `HOME` 的翻译服务失效。最终做法：驱动脚本在最开头替换 `posixpath.expanduser`，把 `~` 解析为环境变量 `FOLIO_TRANSLATOR_HOME`（= `Translator/home`）。`Path.home()` 和 `Path("~").expanduser()` 都经过这个函数，因此所有路径都落在基础目录内；这段代码位于模块顶层，multiprocessing 以 spawn 方式启动的翻译子进程（会以 `__mp_main__` 重新导入驱动脚本）同样生效；而翻译服务启动的外部命令（claude、自定义命令行翻译器）拿到的仍是真实 `HOME`。

实测确认：多次安装和翻译后，用户真实的 `~/.cache/babeldoc`、`~/.cache/pdf2zh_next`、`~/.config/pdf2zh` 均未被修改。

使用“自定义 pdf2zh_next 路径”时不重定向（`redirectsHome = false`），继续使用该安装自己的 `~/.cache/babeldoc`，避免重复下载 300 多 MB 资源。

### 2.2 进程环境

所有子进程都用 `posix_spawn` 启动，环境变量和工作目录完全显式，不继承 App 的环境：

- `PATH=/usr/bin:/bin:/usr/sbin:/sbin`（运行引擎时前面再加入口脚本所在目录），工作目录为 `Translator/tmp`，stdin 为 `/dev/null`。
- 保留：`HOME`、`USER`；代理相关 `http(s)_proxy`、`all_proxy`、`no_proxy`（大小写两种）、`SSL_CERT_FILE/DIR`。
- 固定：`LANG/LC_ALL=en_US.UTF-8`、`PYTHONIOENCODING=utf-8`、`PYTHONUNBUFFERED=1`、`PYTHONNOUSERSITE=1`、`PYTHONDONTWRITEBYTECODE=1`、`NO_COLOR=1`、`COLUMNS=400`（防止 rich 把长路径折行）、`TMPDIR=Translator/tmp/`、`FOLIO_TRANSLATOR_HOME`。
- uv 额外设置 `UV_TOOL_DIR`、`UV_TOOL_BIN_DIR`、`UV_PYTHON_INSTALL_DIR`、`UV_PYTHON_BIN_DIR`、`UV_CACHE_DIR`、`UV_PYTHON_PREFERENCE=only-managed`（不使用 Homebrew / 系统 Python，避免它们升级后环境损坏）、`UV_NO_CONFIG=1`（忽略用户的 uv.toml）。
- API Key 等密钥通过 pdf2zh_next 支持的环境变量传入（`--openai-api-key` → `PDF2ZH_OPENAI_API_KEY`），不出现在进程参数里（`ps` 可见），日志中也会把密钥替换为 `••••`。实测：用环境变量传 Key 后，pdf2zh_next 不再报“API key is required”。
- 子进程使用独立进程组（`POSIX_SPAWN_SETPGROUP`），并用 `POSIX_SPAWN_CLOEXEC_DEFAULT` 防止 App 的文件描述符泄漏给引擎。

## 3. 安装流程（`TranslatorInstallation.install(progress:)`）

| 阶段（`TranslatorInstallPhase`） | 进度区间 | 说明 |
| --- | --- | --- |
| preparing | 0 % | 删除旧的 `tools/`、`bin/` 和完成标记，写入驱动脚本 |
| downloadingUV | 1–3 % | 依次尝试 `Translator/uv/uv`、`~/.local/bin/uv`、`~/.cargo/bin/uv`、`/opt/homebrew/bin/uv`、`/usr/local/bin/uv`（能运行 `--version` 才用）；都没有时从 `github.com/astral-sh/uv/releases/download/0.12.6/uv-<arch>-apple-darwin.tar.gz` 下载，按同名 `.sha256` 校验后解压，并确认能运行 |
| installingPackages | 3–60 % | `uv tool install --python 3.12 pdf2zh-next==2.9.0 --with "bitstring<5"`；解析 uv 输出（`Downloading cpython…`、`Resolved N packages`、`Downloading <包>` / `Downloaded <包>`、`Prepared`、`Installed`）得到粗略进度 |
| downloadingAssets | 60–95 % | 驱动脚本 `warmup`：先校验已有文件，再下载缺失的版面模型、字体、cmap，逐个文件报告进度 |
| verifying | 95–98 % | 用引擎的 Python 导入 pdf2zh_next 并读取版本号 |
| cleaningUp | 98 % | 删除 uv 缓存和临时文件 |
| finished | 100 % | 写入 `installation.json` |

进度只增不减（重试时也不会回退）。取消：取消调用 `install` 的 Task 即可，正在运行的 uv / Python 进程组会被结束，抛出 `TranslatorInstallError.cancelled`。失败时抛出 `TranslatorInstallError.commandFailed(step:summary:logURL:)`，日志在 `logs/install-*.log`。

实测数据：

- uv 输出（非终端模式）示例：`Downloading cpython-3.12.14-macos-aarch64-none (download) (23.8MiB)` → `Resolved 133 packages in 9.57s` → 28 个 `Downloading <包> (大小)` → `Prepared 133 packages in 1m 51s` → `Installed 133 packages in 206ms` → `Installed 3 executables: pdf2zh, pdf2zh2, pdf2zh_next`。空缓存时这一步 132 s；缓存已有时 0.3 s（APFS 克隆）。
- 资源：182 个文件、337 MB。BabelDOC 原本同时发起约 180 个下载（每个连接超时 5 s），第一次实测下载到 169/182 时大量 `ConnectTimeout` 导致失败。驱动脚本因此把并发限制为 6，并最多重试 4 次（已下载并校验通过的文件不会重下）；之后实测 31 s 一次完成。
- 安装完成后 `diskUsage()` 为 1346 MB（使用本机 uv）/ 1385 MB（下载了 uv）。
- 全新安装（`FOLIO_LIVE_NO_SYSTEM_UV=1`、空缓存）逐阶段实测：preparing 0 s → downloadingUV 0–15 s → installingPackages 15–148 s → downloadingAssets 148–180 s → verifying 180–184 s → finished 185 s，共 252 次进度回调，单调递增。

状态检查 `status()` 只看文件，不启动 Python：

- `notInstalled`：既无完成标记也无虚拟环境；
- `broken(reason:)`：有环境没标记（“上次安装没有完成”）、Python 缺失、入口脚本缺失、软件包缺失；
- `installed(version:executableURL:)`：版本取自 `pdf2zh_next-<版本>.dist-info`。

需要深度检查时调用 `verify()`（启动 Python 导入 pdf2zh_next，约 2–5 s）。`uninstall()` 删除除 `logs/` 外的全部内容（uv 留下的只读文件也能删除）。

自定义可执行文件：`customRuntime(executable:)` 先运行 `<路径> --version`（输出 `pdf2zh-next version: 2.9.0`）验证；再定位它背后的 Python（同目录的 `python`、shebang，或 uv 为长路径生成的 `'''exec' '<python>' "$0" "$@"` 跳板），能导入 pdf2zh_next 就走驱动脚本（完整进度），否则退回直接运行命令行（只有开始 / 结束，没有百分比，结果从输出目录按文件名查找）。

## 4. 进度机制：驱动脚本（方案 b）

调研了两种方案：

- **(a) 命令行 + `--report-interval`**：命令行的进度条由 rich 绘制，没有终端（非 TTY）时不输出进度条，只有日志；日志里的结果路径还会被 rich 按 80 列折行。不可靠。
- **(b) 驱动脚本**：`pdf2zh_next.high_level.do_translate_async_stream(settings, file)` 是 pdf2zh_next 自己的命令行和网页界面共用的接口，产出 BabelDOC 的结构化事件 `progress_start / progress_update / progress_end`（含 `stage`、`stage_current`、`stage_total`、`overall_progress` 0–100）、`finish`（`translate_result.mono_pdf_path` / `dual_pdf_path`）、`error`（`error`、`error_type`、`details`）。

采用 (b)。驱动脚本 `folio_pdf2zh_driver.py`（源码内嵌在 `DriverScript.swift`，运行前写入 `Translator/driver/`）：

- `version`：输出版本号。
- `warmup`：下载 / 校验资源，输出 `warmup_start / warmup_progress / warmup_retry / warmup_finish`。
- `translate <pdf2zh_next 参数…>`：把参数交给 pdf2zh_next 自己的 `ConfigManager` 解析（与命令行完全一致，支持全部选项），先做一次资源校验（与官方命令行相同），再调用 `do_translate_async_stream`，把事件转成一行一个的 `@@FOLIO@@{json}` 输出到 stdout；其余日志进入 stderr，全部写入任务日志。

`TranslationJob` 把这些事件转换为 `TranslationEvent`：

- `.stage(String)`：中文阶段名，只在变化时发送。驱动阶段：正在启动翻译引擎 → 检查版面模型和字体 → 连接翻译服务；BabelDOC 阶段：解析 PDF → 检测扫描件 → 分析页面版面 →（识别表格）→ 识别段落 → 识别公式和样式 →（提取术语，仅大模型类服务）→ 翻译段落 → 排版译文 → 嵌入字体 → 生成页面 → 精简字体 → 保存 PDF。
- `.progress(Double)`：0…1，单调递增，变化不足 0.5 % 时不发送。
- `.finished(mono:dual:)`、`.failed(message:logURL:)`、`.cancelled`。

pdf2zh_next 2.9.0 的接口在 2.x 中一直存在（命令行和网页界面都依赖它），驱动脚本只用到它和 `ConfigManager`、`babeldoc.assets.assets` 三处。升级 pdf2zh_next 版本时需要重跑在线测试。

输出文件：`<输出目录>/<原文件名>.no_watermark.<目标语言>.mono.pdf` 和 `….dual.pdf`；大模型类服务还会生成自动提取的术语表 `….glossary.csv`（目前未返回给 App）。

取消：`TranslationJob.cancel()` 向整个进程组发 SIGTERM，3 秒后对仍存活的进程发 SIGKILL。主进程正常退出 2 秒后也会清理一次进程组，防止残留的工作进程占住输出管道、让任务一直不结束。pdf2zh_next 在 multiprocessing 子进程中翻译，这些子进程和驱动在同一进程组，因此一起结束。单元测试用“忽略 SIGTERM 的孙进程”验证了 SIGKILL 兜底。

## 5. 错误提示

`TranslationErrorClassifier` 综合 `error` 消息、`details` 和日志最后 400 行判断原因：

| 原因 | 判断依据（节选） | 提示 |
| --- | --- | --- |
| 额度 / 限流 | HTTP 429、402、Too Many Requests、rate limit、quota、余额不足 | 翻译服务额度不足或请求过于频繁（限流）。请稍后重试、降低 QPS，或换用其他服务。 |
| 认证 | HTTP 401、403、Unauthorized、invalid api key、AuthenticationError | 翻译服务拒绝了请求：API Key 无效、已过期或没有权限。请在设置的“翻译”页检查 Key。 |
| 网络 | Connection error、ConnectTimeout、timed out、nodename nor servname、SSL、代理错误 | 无法连接翻译服务，请检查网络或代理设置后重试。 |
| 组件损坏 | ImportError、No module named、cannot import name | 翻译组件已损坏，请在设置的“翻译”页重新安装组件。 |
| 配置 | … is required、命令找不到 | 翻译服务配置不完整：<原文> |
| 加密 PDF | password、encrypted | PDF 已加密或受密码保护，无法翻译。 |
| 内存 | MemoryError、被 SIGKILL | 内存不足，翻译被中止。 |
| Apple 翻译 | `FOLIO_APPLE_TRANSLATE:` 标记 | 缺少语言包时提示到“系统设置 › 通用 › 语言与地区 › 翻译语言”下载 |
| 其他 | — | 翻译失败：<原始错误首行> |

HTTP 状态码只在 HTTP 语境下匹配（如 `Error code: 429`、`429 Client Error`），避免日志时间戳 `11:41:50,429`、回溯中的 `line 401`、参数名 `rate_limit_params` 被误判——这三种误判都在实测日志中出现过。

注意：pdf2zh_next 在创建翻译器时会先翻译一次 "Hello" 做自检，所以 Key 错误、限流、网络问题通常在“连接翻译服务”阶段（开始后约 15 s）就会失败，错误消息形如 `Translation subprocess initialization error: RetryError[…]`，真正的 HTTP 状态在 `details` 里。

## 7. 通用选项与参数

`TranslationOptions` → `TranslationArgumentBuilder.build(_:appleTranslatorCommand:)`：

| 选项 | 默认 | 参数 |
| --- | --- | --- |
| 源语言 / 目标语言 | en / zh | `--lang-in` / `--lang-out` |

| 双语排版 | 左右 | 上下交替页 `--use-alternating-pages-dual`（仅有双语输出时） |

| 翻译表格文字 | 关 | `--translate-table-text` |
| 兼容模式 | 关 | `--enhance-compatibility` |
| QPS | pdf2zh 默认 4 | `--qps N`（N > 0 时） |
| 忽略缓存 | 关 | `--ignore-cache` |
| 固定参数 | | `--output <目录>`、`--watermark-output-mode no_watermark`、`--report-interval 0.5`、输入文件放最后 |

注意：只翻译部分页码时，输出 PDF 默认仍包含全部页（未翻译的页保持原文），需要只保留译文页时打开 `onlyIncludeTranslatedPages`。

## 8. Apple 系统翻译（离线）

### 8.1 pdf2zh_next 的 clitranslator 协议

阅读 `pdf2zh_next/translator/translator_impl/clitranslator.py`：

- `--clitranslator-command` 用 `shlex.split` 拆成命令和参数；启动时检查命令存在且可执行。
- **每个文本段启动一次进程**：原文写入 stdin（UTF-8），关闭 stdin，读取 stdout 作为译文（去掉首尾空白）。不传语言参数，语言必须写在命令里。
- 非 0 退出码或超时（`--clitranslator-timeout`，默认 60 s）视为失败，按指数退避重试 3 次（2–15 s）；stderr 写入日志。
- 不支持批量；多个段落由翻译线程池并发执行（多个进程同时运行）。
- 后处理命令（如 `jq`）可选。

### 8.2 实现

- 库：`AppleSystemTranslator`（`availability(from:to:)`、`translate(_:from:to:)`、`runCommandLine(arguments:)`、`language(forCode:)`：`zh`/`zh-CN` → `zh-Hans`，`zh-TW`/`zh-HK` → `zh-Hant`）。
- 可执行文件：`folio-apple-translate --from en --to zh`（`--check` 输出 installed / needs-download / unsupported）。退出码：0 成功、1 翻译错误、2 用法错误、3 语言包未下载、4 不支持的语言组合；失败时 stderr 第一行是 `FOLIO_APPLE_TRANSLATE: not-installed en->zh` 之类的标记，`TranslationErrorClassifier` 据此给出中文提示。
- 选择“Apple 系统翻译”时，参数构建器生成 `--clitranslator --clitranslator-command '<助手路径> --from <源> --to <目标>' --clitranslator-timeout 120`。App 需要通过 `TranslationJob(…, appleTranslatorCommand:)` 提供助手的路径（可以是随 App 打包的 `folio-apple-translate`，也可以是 App 主程序的命令行模式，例如 `["…/Folio.app/Contents/MacOS/Folio", "--apple-translate"]`，主程序只需在该参数下调用 `AppleSystemTranslator.runCommandLine`）。

### 8.3 实测结论

- **普通命令行进程可以使用 Translation 框架**：`LanguageAvailability().status(from:to:)` 和 `TranslationSession(installedSource:target:)` 在未打包为 App 的命令行进程里正常工作，不需要 App 包或特殊权限。
- 本机 21 种支持语言中**没有任何已下载的语言包**，en → zh-Hans 的状态为 `supported`（未下载）。此时 `translate` / `prepareTranslation()` 均抛出 `TranslationError.notInstalled`，`isReady == false`，`canRequestDownloads == false`——**命令行进程无法触发语言包下载**。
- 完整链路已在线验证到失败提示：pdf2zh_next → clitranslator → `folio-apple-translate` 返回退出码 3 → 任务失败，提示“Apple 系统翻译缺少所需语言。请在‘系统设置 › 通用 › 语言与地区 › 翻译语言’中下载源语言和目标语言后重试。”（约 13 s，其中含 pdf2zh 的 3 次重试）。
- **未验证实际译文质量和速度**（本机没有语言包，为避免改动系统设置未下载）。下载语言包后可用 `FOLIO_LIVE=1 swift test --filter LiveTests/t4` 复测。

给主 agent 的建议：

1. 开始 Apple 翻译前，App 在进程内调用 `AppleSystemTranslator.availability(from:to:)`；结果为 `.needsDownload` 时，用 SwiftUI 的 `.translationTask(source:target:)` 让系统弹出下载对话框（App 进程 `canRequestDownloads` 才可能为 true），或引导用户打开系统设置。不要直接开始翻译。
2. 由于每段文字都会启动一次进程，建议助手程序体积小、启动快：单独的 `folio-apple-translate` 比完整 App 主程序更合适（后者启动要加载 AppKit / SwiftUI）。

## 10. 给 App 集成的接口

```swift
// 安装 / 状态
let installation = TranslatorInstallation()                 // 默认 ~/Library/Application Support/Folio/Translator
installation.status()                                       // .notInstalled / .installed(version:executableURL:) / .broken(reason:)
try await installation.install { progress in … }            // TranslatorInstallProgress(phase:fractionCompleted:detail:)
try installation.uninstall()
installation.diskUsage()
let runtime = try installation.runtime()                    // 托管安装
let (custom, version) = try await installation.customRuntime(executable: url)   // 用户自己的 pdf2zh_next

// 服务、密钥、选项
TranslationServiceCatalog.all / .service(id:)
let secrets = try SecretStore().secrets(for: service)       // get / set / delete(serviceID:option:)
let request = TranslationRequest(input:, outputDirectory:, serviceID:, fieldValues:, secrets:, options: TranslationOptions(...))

// 翻译
let job = TranslationJob(request: request, runtime: runtime, appleTranslatorCommand: [helperPath])
for await event in job.start() { … }                        // .stage / .progress / .finished / .failed / .cancelled
job.cancel()

// Apple 离线翻译
await AppleSystemTranslator.availability(from: "en", to: "zh")
```

`TranslationJob` 失败时 `.failed(message:logURL:)` 的 `message` 已是中文提示，`logURL` 指向完整日志（供“查看日志”）。配置问题（缺少 Key 等）不启动进程，直接失败。

## 11. 已知问题与注意事项

1. **首个结果较慢**：即使只翻译 1 页也要 30–50 s，其中约 15 s 是启动和翻译器自检的固定开销；14 页论文用 Bing 约 3 分钟。
2. **内存占用高**：峰值约 2 GB，主要来自版面模型。TRANS-04 规定同时只翻译 1 篇是必要的。
3. **免费服务不稳定**：Google 在本机网络下直接 429；SiliconFlow 免费和 Bing 也有频率限制。失败提示会建议降低 QPS 或换服务。
4. **App 退出时**引擎进程不会自动结束（独立进程组），App 应在退出前对正在运行的任务调用 `cancel()`。
5. **沙盒**：当前 App 未启用沙盒，可以执行 `Application Support` 中的 Python。若以后启用沙盒，这套方案需要重新评估。
6. **代理**：引擎只认环境变量形式的代理（`https_proxy` 等），不会自动读取 macOS 系统代理设置；需要时 App 可以把系统代理转换为环境变量（目前模块只透传 App 进程自身的代理变量）。
7. **pdf2zh_next 版本固定为 2.9.0**：驱动脚本依赖 `do_translate_async_stream`、`ConfigManager`、`babeldoc.assets.assets.download_file`；升级前需重跑在线测试。`bitstring<5` 的限制也需要随版本复查。
8. **uv 版本固定为 0.12.6**（仅在本机没有 uv 时下载）；本机已有 uv 时直接使用它（任何能运行的版本）。
9. **术语表文件**：大模型类服务会额外生成 `*.glossary.csv`，目前未通过事件返回。
10. **输出文件名**由 BabelDOC 决定（`<原名>.no_watermark.zh.mono.pdf`），按 TRANS-05 重命名为“原文件名（中文译文）.pdf”等由 App 负责。
