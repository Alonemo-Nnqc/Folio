# Folio 开发计划

> 执行方式：基础层（工程骨架 + FolioCore）由主 agent 按 TDD 完成；三个相互独立的模块（元数据检索引擎、引用导出、Zotero 读取）各开一个 git worktree + 分支，交给子 agent 并行开发，完成后合并回 `main`；UI 由主 agent 在 `main` 上同步开发并负责最终集成与验收测试。每个任务结束都要编译、测试通过并提交（Conventional Commits）。

**目标**：按 `doc/需求文档.md` v1.1 交付可签名运行的 macOS 应用 Folio。

**架构**：
- `Packages/FolioCore`：本地 Swift Package，包含 4 个库 target（FolioCore、FolioMetadata、FolioCitation、FolioZotero）和对应的测试 target，全部可用 `swift test` 独立测试。
- `Folio`：App target 由 XcodeGen 生成的 Xcode 工程构建，只负责 UI 与服务编排，依赖上面的 Package。
- 数据以 SQLite（GRDB）为唯一可信来源。App 通过 GRDB `ValueObservation` 拿到不可变快照 `LibrarySnapshot`，列表内容由纯函数 `ViewResolver` 根据快照计算得出。

**技术栈**：Swift 6.4（语言模式 6）、SwiftUI + AppKit（NSOutlineView）、GRDB.swift 7.11.x、PDFKit、Vision（扫描版 PDF 的 OCR 兜底）、QuickLookUI、JavaScriptCore + citeproc-js 2.4.63、CSL 官方样式、XcodeGen、Swift Testing。

## 全局约束

- 最低系统：macOS 26.0；Xcode 27 / Swift 6.4；架构 arm64 + x86_64。
- Bundle ID `com.nnqc.Folio`；Team `2WJC7GTSV4`；使用 Apple Development 证书签名；不开 App Sandbox，开启 Hardened Runtime。
- 界面文案全部为简体中文（开发语言 zh-Hans）。
- 文献库默认位置：`~/Folio`（`Folio.sqlite` + `Files/`）。
- 第三方依赖只有 GRDB.swift（SPM）；citeproc-js、CSL 样式和 locale 文件作为资源打包。
- 不得在 `~/Zotero` 下写入任何内容。测试时只复制 Zotero 数据到临时目录后再读。
- 截图验证只截取 Folio 自己的窗口（`screencapture -l <windowID>`），不截整个屏幕。
- 提交信息使用 `feat:` / `fix:` / `test:` / `docs:` / `chore:` / `refactor:` 前缀，结尾附 `Co-Authored-By: Claude Code <noreply@anthropic.com>`。

## 三、数据库结构（Migration v1）

```sql
CREATE TABLE item (
  id TEXT PRIMARY KEY, kind INTEGER NOT NULL,            -- 0 regular 条目, 1 standalone 独立文件
  type TEXT NOT NULL, title TEXT NOT NULL, authors TEXT NOT NULL DEFAULT '[]',   -- authors 为 JSON
  year INTEGER, date TEXT, source TEXT, volume TEXT, issue TEXT, pages TEXT, publisher TEXT,
  doi TEXT, arxivId TEXT, isbn TEXT, url TEXT, abstract TEXT, citationKey TEXT,
  rating INTEGER NOT NULL DEFAULT 0, readStatus INTEGER NOT NULL DEFAULT 0,    -- 0 未读 1 在读 2 已读
  defaultFileId TEXT, metadataState INTEGER NOT NULL DEFAULT 0,               -- 0 none 1 pending 2 failed 3 networkFailed 4 resolved
  retryCount INTEGER NOT NULL DEFAULT 0, originItemId TEXT,                    -- originItemId：单独删除的文件原属条目
  dateAdded DATETIME NOT NULL, dateModified DATETIME NOT NULL, trashedAt DATETIME);
CREATE INDEX item_doi ON item(doi); CREATE INDEX item_trashed ON item(trashedAt);
CREATE TABLE file (
  id TEXT PRIMARY KEY, itemId TEXT NOT NULL REFERENCES item(id) ON DELETE CASCADE,
  relativePath TEXT NOT NULL UNIQUE, originalName TEXT NOT NULL, size INTEGER NOT NULL,
  sha256 TEXT NOT NULL, originalSha256 TEXT NOT NULL, modifiedAt DATETIME NOT NULL,
  dateAdded DATETIME NOT NULL, fulltextState INTEGER NOT NULL DEFAULT 0);    -- 0 未索引 1 已索引 2 不适用
CREATE INDEX file_item ON file(itemId); CREATE INDEX file_sha ON file(sha256); CREATE INDEX file_osha ON file(originalSha256);
CREATE TABLE libraryGroup (
  id TEXT PRIMARY KEY, parentId TEXT REFERENCES libraryGroup(id) ON DELETE CASCADE,
  name TEXT NOT NULL, position DOUBLE NOT NULL, dateCreated DATETIME NOT NULL);
CREATE TABLE itemGroup (
  itemId TEXT NOT NULL REFERENCES item(id) ON DELETE CASCADE,
  groupId TEXT NOT NULL REFERENCES libraryGroup(id) ON DELETE CASCADE,
  dateAdded DATETIME NOT NULL, PRIMARY KEY (itemId, groupId));
CREATE TABLE tag (id TEXT PRIMARY KEY, name TEXT NOT NULL UNIQUE COLLATE NOCASE, colorHex TEXT NOT NULL, position DOUBLE NOT NULL);
CREATE TABLE itemTag (
  itemId TEXT NOT NULL REFERENCES item(id) ON DELETE CASCADE,
  tagId TEXT NOT NULL REFERENCES tag(id) ON DELETE CASCADE, PRIMARY KEY (itemId, tagId));
CREATE TABLE itemOrder (
  scope TEXT NOT NULL, itemId TEXT NOT NULL REFERENCES item(id) ON DELETE CASCADE,
  position DOUBLE NOT NULL, PRIMARY KEY (scope, itemId));
CREATE TABLE viewSort (scope TEXT PRIMARY KEY, sortColumn TEXT, ascending BOOLEAN NOT NULL);
CREATE VIRTUAL TABLE fulltext USING fts5(fileId UNINDEXED, content, tokenize = 'unicode61 remove_diacritics 2');
```

关键语义：
- **成员关系保留**：条目移到回收站时保留 `itemGroup` 行，视图查询排除 `trashedAt IS NOT NULL`。恢复时只清空 `trashedAt`，自然回到仍存在的分组（TRASH-05）；分组被删除时通过级联删掉成员关系，所以恢复后没有分组的条目会出现在"未分组"。
- **单独删除文件**（TRASH-03）：新建一个 standalone 条目（`originItemId` = 原条目，`trashedAt` = 现在），把文件挂到它下面。回收站里因此只有"条目"这一种对象。恢复时，原条目存在且未删除就把文件挂回去，并删除这个临时条目；否则清空 `trashedAt` 和 `originItemId`，它就成为普通的独立文件。
- **自定义顺序**：视图内的排序值为 `itemOrder.position`；没有记录的条目用 `-dateAdded.timeIntervalSince1970`，因此新条目永远排在最前。拖拽排序时，把该视图当前显示的完整顺序重写为 0…n-1。
- **去重指纹**：文件级去重同时比对 `sha256` 和 `originalSha256`（导入时的哈希）。这样即使 PDF 被"预览"加了批注、内容已经变化，再拖入原文件仍能识别为重复。
- **视图键**：`all`、`unfiled`、`trash`、`group:<id>`、`tag:<id>`，用于 `itemOrder.scope` 和 `viewSort.scope`。

**Task 1.2 纯函数工具**

  - `TitleNormalizer.similarity(a,b)`：基于词元的 Dice 系数和标准化 Levenshtein 距离，取两者较大值，范围 0…1。
  - `DuplicateMatcher.isSameWork(Metadata, Metadata)`：DOI 相同；或者双方都没有 DOI 时，标准化标题相同、年份相同、第一作者姓相同。

  - `CitationKeyGenerator`：带音调的姓（Müller → muller）；冲突时生成 a/b 后缀。

- 提交：`feat(core): add normalizers, naming and citation keys`

**Task 1.3 FileStore 与导入（STORE-*、DUP-01/02、META-01 的数据部分）**
- `FileStore(root:)`，管理 `Files/` 目录：

  - `rename(relativePath, toBase:) -> relativePath`。
  - `delete(relativePath)`、`url(for:)`。

  - `ImportOutcome` 取值：`.imported(itemId, isPDF)`、`.duplicateFile(existingItemId, addedToGroup: Bool)`、`.duplicateInTrash(existingItemId)`、`.failed(URL, String)`。
  - 处理流程：
    1. 计算哈希。
    2. 与未删除条目的文件比对 sha256 / originalSha256。

**Task 2A：FolioMetadata 元数据检索引擎** —— 分支 `feature/metadata-engine`

公共 API：


内部组件（各自一个文件）：
- `PDFFacts`：内嵌 Title/Author、XMP 中的 DOI、前两页文本、首页文本行及其字号（来自 `PDFPage.attributedString` 的字体属性）、文件名。首页没有文字时，用 Vision `VNRecognizeTextRequest` 对首页渲染图做 OCR。
- `IdentifierExtractor`：
  - DOI 正则：`10\.\d{4,9}/[^\s"<>]+`，并去掉尾部的 `.,;)]`。
  - arXiv 新格式 `\d{4}\.\d{4,5}(v\d+)?`（需出现在 `arXiv:` 之后、arxiv.org URL 中或文件名中），以及旧格式 `[a-z\-]+(\.[A-Z]{2})?/\d{7}`。
  - ISBN-10/13，带校验位验证。
  - 结果按出现位置排序：首页 > 第二页 > 文件名 > XMP。
- `TitleGuesser`：取首页字号最大的若干行，合并连续的同字号行，过滤掉以下内容：页眉、期刊名、"arXiv:"、邮箱、少于 3 个单词的行。内嵌 Title 看起来可信时也加入候选；以 "Microsoft Word -"、文件名样式或全大写短词开头的不算可信。
- 数据源客户端（各自负责解析与字段映射）：
  - `CrossrefClient`：`/works/{doi}`、`/works?query.bibliographic=&rows=5`。
  - `DOIContentNegotiationClient`：请求 `https://doi.org/{doi}`，`Accept: application/vnd.citationstyles.csl+json`，用于 DataCite 等非 Crossref 的 DOI。
  - `ArxivClient`：`export.arxiv.org/api/query?id_list=` 和 `search_query=ti:`，返回 Atom，用 XMLParser 解析；类型为 preprint，source 为 "arXiv"，doi 为 `10.48550/arxiv.<id>`。
  - `OpenAlexClient`：`/works?search=&per-page=5`；摘要由 `abstract_inverted_index` 还原。
  - `DBLPClient`：`/search/publ/api?q=&format=json&h=5`。
  - `OpenLibraryClient`：`/isbn/{isbn}.json`，作者需要再请求一次。
- `CandidateScorer`：
  - 计算标题相似度：候选标题分别与首页文本的滑动窗口、与猜测的标题比较，取最大值。
  - 作者校验：候选的前 3 位作者中，有姓氏出现在首页文本里。
  - 采纳条件：标题相似度 ≥ 0.90 且作者校验通过；或者标题相似度 ≥ 0.97。
  - 多个候选都达标时，优先级：有 DOI 的正式发表版本 > DBLP > arXiv；但 PDF 本身带 arXiv 标识时优先采用 arXiv 版本。
- 编排（`MetadataEngine`）：
  1. 先提取 facts。
  2. 同时启动标识符查询（最多 3 个 DOI 加 1 个 arXiv ID）和标题检索（Crossref、OpenAlex、DBLP、arXiv 四路）。
  3. 标识符结果经过标题校验（返回的标题与首页文本的相似度 ≥ 0.85）后立即返回。
  4. 否则等到标题检索全部返回或超时，取最佳达标候选。
  5. 所有请求都因 `URLError`（未联网、超时、DNS 失败等）失败 → `.networkError`；否则没有达标候选 → `.notFound`。
  6. 每个 host 有最小请求间隔：export.arxiv.org 为 1 秒，其余为 0。
  7. 设置 User-Agent：`Folio/1.0 (mailto:<mailto>)`。
- 字段规范化：
  - DOI 转小写。
  - 标题去掉 HTML/JATS 标签，合并空白。
  - 作者统一拆成 family/given。
  - 年份依次取 published-print → published-online → issued → created。
  - Crossref 的 type 映射为 ItemType：journal-article → journalArticle，proceedings-article → conferencePaper，posted-content → preprint，book → book，book-chapter → bookChapter，dissertation → thesis，report → report，dataset → dataset。
- 测试：
  - 单元测试：每个客户端用录制的 JSON/XML fixture（放在 `Tests/FolioMetadataTests/Fixtures/`）验证解析结果。
  - 单元测试：`IdentifierExtractor`、`TitleGuesser`（用 CoreText 生成的 PDF）、`CandidateScorer`。
  - 单元测试：编排逻辑用 `MockHTTPClient`，覆盖以下场景：找到 DOI、只有 arXiv ID、只有标题、参考文献中的 DOI 被标题校验拒绝、全部网络错误 → `.networkError`。
  - 在线评测 `LiveEvaluationTests`：仅当环境变量 `FOLIO_LIVE=1` 时运行。
    - 读取 `FOLIO_EVAL_DIR`（由主 agent 从 Zotero 复制过来的 PDF 样本）和 `FOLIO_EVAL_TRUTH`（JSON 真值：文件名 → 标题/DOI）。
    - 输出命中率、错误匹配数、每篇耗时的 P50/P90。
    - 验收标准：命中率 ≥ 85%，错误匹配为 0，P50 ≤ 3 秒，P90 ≤ 5 秒。

  - 右键菜单按 SIDE-06/07、SIDE-14 的规则由 `menuNeedsUpdate` 动态构建。
  - 拖拽规则集中在纯函数 `SidebarDragRules.validate(source:, target:, childIndex:) -> DropDecision` 中，并写单元测试。
    - 分组拖到另一个一级分组上：成为其子分组。
    - 分组拖到同级位置：调整顺序。
    - 子分组拖到一级分组之间的间隙：提升为一级分组。
    - 条目拖到自建分组：加入该分组；拖到当前视图对应的分组：不做任何事。
    - 条目拖到回收站：删除；拖到标签：添加该标签。
    - Finder 文件拖到分组：导入到该分组；拖到"所有文献"或"未分组"：只导入。
    - 拖到内置分组区域一律拒绝。
- 验收：
  - XCUITest 覆盖：新建分组并重命名、新建子分组（子分组的菜单里没有"新建子分组"）、删除分组时弹出确认、右键回收站显示"清空回收站"。
  - 截图核对分隔线和缩进效果。

**Task 3.3 条目列表（LIST-*、FILE-01…04、DND-01/04/06、META-01 转圈）**
- `ItemOutline`（NSOutlineView），行高 26。
  - 列定义：每列包含 identifier、中文标题、默认宽度、排序键、默认是否显示。
  - 用 `autosaveName` 保存列的宽度、顺序和隐藏状态。
  - 列头右键菜单用来勾选显示的列；标题列不能隐藏。
- 单元格：
  - 标题：展开箭头由系统提供。图标规则：条目为 `doc.text`；独立文件用 `NSWorkspace` 文件图标；检索中换成 `NSProgressIndicator` 小号转圈，并显示副标题"正在检索元数据…"。文件子行显示文件名，默认文件右侧加"默认"胶囊。
  - 标签：`TagChipsView`，用自绘胶囊实现。
  - 阅读状态：蓝点 / 半圆 / 空。
  - 评分：★ 字符。
  - 其余为文本；空值显示"—"。
- 快照变化时：
  - 重新计算 rows，并与上次比较。
  - 结构有变化时 `reloadData`，然后恢复展开状态和选中项（按 id）。
  - 只有内容变化时，对对应行做 `reloadData(forRowIndexes:)`。
- 鼠标与键盘：
  - 双击或回车：`FileOpener.open`，规则见 LIST-08 和 OPEN-03。
  - 空格：`QLPreviewPanel`（由 `QuickLookSupport` 负责数据源）。
  - → / ← 展开或折叠。
  - ⌫ / ⌘⌫ 的行为见 TRASH-02。
- 右键菜单：由 `ItemMenuBuilder.menu(for context) -> [MenuEntry]` 生成。它是纯函数，先产出菜单模型再转换成 NSMenu，并写单元测试，覆盖三种视图（自建分组、内置分组、回收站）和三种行（条目、独立文件、文件子行）。
- 拖拽：
  - 拖出：条目提供两种数据——私有类型 `com.nnqc.folio.items`（JSON：itemIds 和来源视图）以及默认文件的 fileURL；文件子行只提供 fileURL。
  - 列表内拖放：只接受私有类型，放在行与行之间时调整顺序（`setDropItem(nil, dropChildIndex:)`）；搜索状态下拒绝。
  - Finder 拖入：列表不注册 fileURL 类型。由 SwiftUI 层的 `.onDrop(of: [.fileURL])` 接收 Finder 拖来的文件，并显示 `DropOverlay`；拖动内容包含私有类型时忽略，不显示浮层。
- `DropOverlay`：
  - `glassEffect(in: RoundedRectangle(cornerRadius: 24))` 的面板，四周有虚线描边。
  - 文档图标用 `symbolEffect(.bounce)` 做动画，下方显示"松开以添加 N 个文件"。
  - 出现时淡入并从 0.96 放大到 1；松手后缩小并淡出。
- 空状态：`ContentUnavailableView`。
- 验收：
  - XCUITest：列头右键菜单能隐藏"来源"列；双击能打开文件（用 `openWithMode` 的测试钩子记录打开的路径）；右键文件行能"设为默认打开文件"，完成后"默认"徽标会移过去。
  - 截图核对转圈图标和标签截断效果。

**Task 3.4 检查器（INSP-*）与标签界面（TAG-*）**
- `InspectorView` 顶部是分段控件"元数据 | 标注"。
- `MetadataInspector`：
  - 用 `Form`（`.grouped` 样式、`controlSize(.small)`）按参考图排版。
  - 标题为大号可编辑多行文本；作者用 `AuthorsEditor`（增删和拖动排序）。
  - 其他字段用 `LabeledContent` 加 plain 样式的 TextField，提交时调用 `library.updateItem`。
  - DOI / URL 旁边有打开按钮；摘要可以折叠。
  - 标签、分组用胶囊显示：胶囊上的 × 用于移除，"+" 分别弹出 `TagPickerPopover` 和分组菜单。
  - 另有 `RatingControl`、阅读状态 Picker，底部是文件列表。
  - 独立文件显示 `StandaloneFileInspector`。
- `AnnotationsInspector`：在后台读取标注，按文件分组显示，带搜索框和"打开 PDF"按钮。
- 标签组件：
  - `TagChip`：SwiftUI 胶囊，最大宽度 90，`.truncationMode(.tail)`。
  - `TagPickerPopover`：搜索框、带勾选的已有标签列表、"新建标签「x」"入口，行上右键可以编辑或删除标签。
  - `TagEditorSheet`：名称输入框，10 色调色板加 `ColorPicker`，重名时在输入框下显示红字提示。
  - `TagPalette`：红 #FF3B30、橙 #FF9500、黄 #FFCC00、绿 #34C759、薄荷 #00C7BE、青 #32ADE6、蓝 #007AFF、靛 #5856D6、紫 #AF52DE、粉 #FF2D55，外加灰色 #8E8E93 作为导入时的默认色。
- 验收：
  - XCUITest：新建标签后在条目上显示；编辑标签颜色后条目上同步变化；删除标签时弹出确认。
  - 截图核对检查器排版。

**Task 3.5 轻提示、弹窗、设置**
- `ToastCenter` 加上 `ToastOverlay`：底部居中的 glass 胶囊，2.5 秒后消失，同类提示会合并。
- `DuplicatePrompter`：用 NSAlert 以 sheet 形式弹在主窗口上。多个提示依次排队；带 suppression 复选框"对其余项执行相同操作"。
- `IdentifierAddSheet`、`ManualMatchSheet`：输入框加结果列表，调用 `MetadataEngine.search`。
- `ZoteroImportSheet`：
  - 自动定位数据目录，可以"选择…"其他目录。
  - 用 `probe` 的结果显示将导入的数量，以及"同时导入自动标签（N 个）"开关。
  - 导入时显示进度条，完成后显示摘要。
- `SettingsView`：包含通用、文献库、检索、导入四页，内容见需求 4.16。更改文献库位置的流程：选择目录 → 关闭数据库 → 移动 `~/Folio` → 用新路径重新打开。

### 阶段 4：合并与集成（主 agent）

- 依次把 `feature/metadata-engine`、`feature/citation`、`feature/zotero-import` 合并回 main（`--no-ff`），解决冲突后运行全部测试。
- `ImportCoordinator`：
  - `importFiles(urls, toGroup)` 和 `open -a` 打开的文件都走这个入口；拖入文件夹时递归收集其中的 PDF。
  - 导入结果：
    - 重复的文件 → 轻提示。
    - 重复的文件在回收站中 → 询问是否恢复。
    - 导入的是 PDF → 进入 `RetrievalQueue`（最多 4 个并发）。
  - 检索结果：
    - `.found` → `applyMetadata`；返回 `.duplicateItem` 时交给 `DuplicatePrompter`，按用户选择执行 merge 或 discard。
    - `.notFound` → 状态设为 failed，并合并成一条轻提示。
    - `.networkError` → 状态设为 networkFailed；`NetworkMonitor` 检测到网络恢复后自动重试，最多 3 次。
  - 启动时把状态仍为 pending 的条目重新放回队列。
- `FulltextIndexer`：以 utility 优先级串行处理 `filesNeedingFulltext`。App 每次变为活跃时调用 `refreshFingerprints`，变化的文件重新索引。
- 引用：
  - 菜单"复制引用 ▸"把 `plainText` 和 `html` 同时写入剪贴板。
  - "导出 BibTeX…"弹出 `NSSavePanel`，导出选中项，或当前视图的全部条目。
- 回收站自动清理：启动时以及之后每 24 小时执行一次 `purgeTrash(olderThan: 30 天前)`。
